### 点検結果 — 穴は2つあった

8/2 に潰したのは **記事 → /shop → /chat** の経路だけだった。点検の結果、
オフィスアート導線には**中継ページが3枚**あり、うち2枚が未対応だと判明した。

```
SEO記事(tax-guide / size-guide) ─┬─→ /shop      ─→ /chat   … 8/2 対応済
                                  └─→ /office-art ─→ /chat   … ★穴1（未対応）
/business ─→ /office-art ─→ /chat                            … ★穴2（UTMすら無し）
```

- **穴1: `/office-art` ハブ**。記事のフッターCTA「オフィスアートを見る」（`utm_source=tax_guide`）で
  ハブに着地した後、ハブの全CTAが静的固定URL `utm_source=office_art` のため、
  **チャット着地時点で記事名が消えていた**。/shop と完全に同型の潰れ。
  しかも記事→ハブ→チャットは記事→交易所→チャットより自然な導線で、**こちらが主経路の可能性が高い**。
- **穴2: `/business` → `/office-art` のクロスセルリンク**。UTMもクリック計測も一切付いていなかった。
  音楽の法人客をオフィスアートへ送客する唯一の経路なのに、**送客が起きたことすら観測できない**状態だった。

### 実装

1. **`src/lib/use-inbound-search.ts`（新規）** — `useInboundSearch()` フックを切り出し。
   8/2 に `BuyButton.tsx` 内へ private に書いた同名関数を共通化した。
   `useSearchParams()` を使わずマウント後に `window.location.search` を読む方針（＝静的生成を維持する理由）を
   フック側のコメントに集約し、利用箇所ごとに書き写す必要をなくした。
2. **`src/components/cta/AttributedCta.tsx`（新規）** — 流入元を保つ汎用CTA。
   `href` / `event` / `eventProps` を受け、`withInboundAttribution()` で合成した href で `next/link` を描画し、
   `track()` に**合成後の `to`** を渡す。アトリビューション規約の実装が `src/lib/utm.ts` 1箇所に留まる。
3. **`src/app/office-art/page.tsx`** — CTA6本すべてを `AttributedCta` に置換（`next/link` の直接importは不要になり削除）。
   新イベント3種を発火:
   - `office_art_cta_click`（`location`: `hero` / `edition_story` / `footer`）— ハブのどの位置が相談に効くか
   - `office_art_dossier_click`（`slug`）— 検討の深さ
   - `office_art_guide_click`（`guide`）— ハブから記事への回遊
4. **`src/app/business/page.tsx`** — クロスセルリンクに
   `utm_source=business&utm_campaign=biz_cross_sell` を付与し、`office_art_cross_click` で計測。
   あわせて文言を「即時償却対象となる場合あり」→
   「**少額減価償却資産の特例**の対象となる場合あり」に修正し（制度名として「即時償却」は不正確）、
   「※一般的な情報であり、税務上の取扱いは必ず顧問税理士にご確認ください」を併記した。
   /business には税務注記が無いまま税制メリットに言及していたため、これは表示上の不備の是正でもある。
5. **`src/app/shop/BuyButton.tsx`** — 共通フックを import する形に整理（挙動不変）。
6. **`docs/analytics-events.md`** — 「3ホップ問題」の節を「**中継ページ問題**」に一般化。
   経路図・適用箇所の一覧・新イベント4種を追記し、
   「`via` は最後の中継ページのみを示す（経路全体は保持しない）」という既知の制約を明記した。
