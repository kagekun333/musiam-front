# Fable 5 実行プロンプト（コピペ用）

以下の区切り線の間がそのままFableに渡すプロンプト本文。渡す前に、`docs/PRODUCT_AND_AFFILIATE_STRATEGY.md` と `docs/LETTERS_ROADMAP.md` を同じ会話/セッションでFableが読める状態にしておくこと（同じリポジトリ内なので、パスを渡せば読みに行けるはず）。

---

あなたは伯爵MUSIAM（AI×人間で音楽・書籍を量産する個人クリエイターのサイト）の「伯爵の手紙」552通の全面リライトを担当する。この会話には人間が張り付いていない。判断に迷っても「〜してよいですか？」と聞き返さず、自分の判断で進め、その判断根拠を作業ログに残すこと。

**最終ゴール**: 読者が読んで面白い・見ごたえのある手紙にすること。Amazonアフィリエイトの商品紹介はその手段であって目的ではない。広告っぽさが勝った時点で失敗とみなす。

**読むべき前提資料**（作業前に必ず目を通すこと）:
- `docs/PRODUCT_AND_AFFILIATE_STRATEGY.md` — ジャンル戦略、頻度ルール、「後出しじゃんけん」による先見性の演出の原則（第0章）
- `docs/LETTERS_ROADMAP.md` — 手紙の構成テンプレート分析、`{sponsored}`記法の技術仕様
- `src/lib/letters.ts` — 実際のMarkdownパーサー・`renderMarkdown()`の実装。ここに書かれていない記法は使えない
- `content/letters/*.md` — 552通の実データ（frontmatterに`title`/`date`/`description`/`keywords`、本文はMarkdown）

**中核となる書き方の原則（最重要）**
過去の日付の手紙は、その日付時点の熱量・速報トーンで書きながら、実際に選ぶ商品は「その後ヒットした・定番化したと現時点で分かっているもの」に限定する。ハズレを掴まされない「後出しじゃんけん」を意図的に使う。これは時事ガジェット枠に限らず全ジャンルに適用する原則。

**やってよいこと（判断は任せる）**
- 552通を読み込み、ジャンル戦略表に照らしてどの手紙にどの商品ジャンルが合うか判断する
- 実際の本文リライト（見出し構成・長さを含め、`LETTERS_ROADMAP.md`で指摘されている「546通が同一テンプレート」という単調さを崩してよい。ただし署名「**ABI伯爵**」は毎回維持）
- Amazon商品のリサーチ（実在する商品か、日本のAmazon.co.jpで購入可能か）

**やってはいけないこと（厳守）**
- 実在しないASIN・URLを創作しない。実在を確認できない商品は、本文に組み込まずスキップするか、`<!-- TODO: ASIN未確認 商品名: XXX -->` のようなコメントで明示して人間の確認待ちにする
- アフィリエイトリンクを付ける際は必ず `[表示テキスト](URL){sponsored}` の記法を使う。タグは `?tag=hakusyaku04-22` で統一する
- 1通につき商品紹介は基本1つまで
- 552通すべてに商品を入れようとしない。合わない回は無理に紹介を入れず素通りしてよい
- 家電・ドローン・レコード・NFT・グッズ・コーヒーOEMなど、`docs/OTHER_PRODUCT_TRACKS.md`側の話題には手を出さない（今回のスコープ外）
- 本番への反映（git push）は行わない。ファイルの変更はローカルに留める

**進め方について**
最初に552通全体を俯瞰し、どういう順序・バッチサイズで進めるかは自分で計画してよい。ただし、以下は必ず行うこと。
1. 作業計画・判断根拠・進捗を `docs/FABLE_WORKLOG.md` に書き出しながら進める（このファイルを自分の外部メモリとして使い、会話が長くなっても記憶に頼らずここを読み返すこと）。少なくとも「ジャンル×手紙の対応表」と「実際にリライトした手紙一覧（元の内容との差分概要）」はここに記録する。
2. 何かを「完了」と報告する前に、実際に編集したファイルの中身をツールで読み直して確認してから報告する（自己申告ではなく証拠に基づいて報告する）。
3. 作業の粒度は自分で決めてよいが、途中経過が`FABLE_WORKLOG.md`から追える状態を常に保つこと（人間が後から差分だけ見て安全か判断できるようにするため）。

以上を踏まえ、まず552通の状況を把握し、あなた自身の計画を`docs/FABLE_WORKLOG.md`に書き出すところから始めてよい。
