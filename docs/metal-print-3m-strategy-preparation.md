# 伯爵MUSIAM メタルプリント月商300万円 — 戦略・実行計画準備ブリーフ

更新日: 2026-07-18
状態: `READY_FOR_STRATEGY_DESIGN / SALES_HOLD`

## 1. この準備の目的

次Sprintで、願望ベースではなく検証可能な「月商300万円戦略」と「30/60/90日実行計画」を作れる状態にする。

月商300万円の定義は、予約や問い合わせではなく、**返金・取消のない全額決済売上が月3,000,000円以上**とする。現行候補の標準成約価格300,000円なら10件、4 Edition × 各3点を完売する運用なら12件・3,600,000円である。

## 2. State Lock

### 確認済み資産

- 月次ミッション、価格帯、週次ファネル、停止条件を機械検証するSales OSがある。
- 4候補作品は、原画ソース3000 × 3000pxとオーナー販売許可が確認済み。
- 4つのCollector Dossier草案、候補LP、Chatハンドオフ、PostHogイベント案がある。
- 原画監査では216作品中158作品が暫定的な3000px基準を満たした。
- `npm run validate:metal-print-mission` はPASS。価格ミックス最悪ケースでも12件完売時3,060,000円となる。

### 現在の停止理由

`HOLD / rights_and_print_proof`

販売開始に必要な次の証拠が未確定である。

1. 印刷会社が承認する最終サイズ、素材、表面、色管理、取付方法
2. 4作品の実物proofと人間による視覚承認
3. 1点原価、梱包、送料、決済手数料、再製造リスクを含む限界利益
4. 製造・発送納期、破損、返品、返金、再製造の責任分界
5. 実在する見込み客リストと、価格受容性を示す顧客インタビュー
6. 決済WebhookとEdition残数台帳の同期仕様

## 3. 戦略設計で確定する6つの意思決定

| Decision | 決める内容 | 判断材料 | Gate |
|---|---|---|---|
| 顧客 | 個人コレクター、音楽ファン、設計・ホテル・店舗、贈答の優先順位 | 15〜20件の問題・購買インタビュー | `ICP_LOCK` |
| 商品 | 作品、サイズ、仕上げ、Edition、証明書、設置体験 | vendor proof、設置写真、権利台帳 | `OFFER_LOCK` |
| 価格 | 330,000円/300,000円の成立条件。165,000円例外枠の是非 | 粗利表、価格感度、ブランド毀損リスク | `PRICE_LOCK` |
| 獲得 | owned、紹介、個別営業、建築・宿泊施設提携の配分 | チャネル別CAC、商談化率、リードタイム | `CHANNEL_LOCK` |
| 販売 | Dossier、相談、決済、在庫、納品までの責任者とSLA | E2Eテスト、FAQ、契約・表示確認 | `SALES_READY` |
| 計測 | 売上、粗利、ファネル、在庫、返品、納期のsource of truth | Stripe/PostHog/台帳の定義 | `MEASUREMENT_LOCK` |

## 4. 次の戦略で比較する収益シナリオ

単一案に固定せず、proofと顧客証拠を得てから次の3案を比較する。

| シナリオ | 月次構成 | 売上 | 主なリスク |
|---|---:|---:|---|
| Collector D2C | 300,000円 × 10件 | 3,000,000円 | 毎月10人の新規高単価購入者獲得が重い |
| Capsule sold-out | 300,000円 × 12件 | 3,600,000円 | 4 Editionすべての需要予測が必要 |
| Hybrid | 個人6件 + 法人/空間案件2〜4件 | 3,000,000円以上 | 仕様・見積・納期が案件ごとに膨張しやすい |

戦略本編では売上だけでなく、`粗利額 / 現金回収期間 / CAC / 制作工数 / 納期遵守 / 返金率`で採用案を決める。

## 5. 戦略作成前のEvidence Sprint

### Track A — 商品・製造

- 2社以上から同一条件の見積とproof仕様を取得する。
- 4候補のうち最低1作品をproof対象として選ぶ。
- 色、反射、傷、エッジ、重量、取付、梱包を同じレビューシートで判定する。
- 1点、3点、12点のlanded costと再製造引当を計算する。

停止条件: 外部送信、画像アップロード、proof発注、支払はHuman Approval後。

### Track B — 顧客・需要

- 仮説ICPを4群に分け、各群の購入動機、置く空間、予算、決裁者、購入時期を定義する。
- 既存の許諾済み接点から15〜20件のインタビュー候補を作る。
- 価格を売り込む前に「現在何を飾っているか」「30万円の作品を買う条件」「物証として何が必要か」を確認する。
- `interest`、`qualified`、`price-accepted`、`purchase-intent`を混同しない。

停止条件: 個別連絡、CRM登録、メール送信、広告出稿はHuman Approval後。

### Track C — 販売・計測

- `View → Dossier → Qualified conversation → Purchase intent → Checkout → Paid` のイベント定義を固定する。
- Stripe webhookだけを決済済みのsource of truthとする。
- Edition IDごとの3枠、返金、取消、再決済を扱う状態遷移を設計する。
- Chat本文を分析基盤へ送らず、collector intentなど必要最小限の属性だけを計測する。

停止条件: Stripe、PostHog、外部CRM、production設定変更はHuman Approval後。

## 7. 30/60/90日計画を作る際の基準

- 0〜30日: proof、粗利、顧客15〜20件、1つのICPと1つのofferをlock。
- 31〜60日: 承認済みの小規模Collector Previewで、実測ファネルと価格受容性を検証。
- 61〜90日: 再現性が出たチャネルだけを増幅し、月商300万円run-rateを判定。
- proof不合格、限界利益不足、購入意向不足の場合は、公開前に商品・価格・ICPを修正する。
