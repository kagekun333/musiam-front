### 問題

オフィスアートのオーガニック導線は **SEO記事 → /shop → /chat** の3ホップ。
/shop のCTAは固定URL（`utm_source=shop`）のため、最後のホップで記事名が上書きされ、
`tax-guide` と `size-guide` のどちらが法人リードを生んだのかが**構造的に分離不能**だった。
記事を増やしても、どれが効いたか判定できない状態。

### 実装

1. **`src/lib/utm.ts`（新規）** — `withInboundAttribution(baseHref, incomingSearch)`
   - `utm_source` / `medium` / `campaign` / `term` は**獲得元(first touch)を優先**して引き継ぐ
   - `utm_content` は「実際に押されたCTA」を示す欄として base 側（`restock_notify` 等）を維持
   - 流入元の `utm_content` は `inbound_content` に退避し、情報を捨てない
   - 経由地を `via=shop` として記録
   - `space` / `work` / `gclid` / `fbclid` / `ref` は base に無い場合のみ引き継ぐ
   - 値は `[\w.\-:/]` 以外を `_` に正規化し64文字で切る（URL汚染・注入防止）。着地パスは base 固定のためオープンリダイレクトの余地なし
2. **`src/app/shop/BuyButton.tsx`** — リードCTA2種（`shop_restock_notify` / `shop_order_inquiry`）に適用。
   `useSearchParams` ではなく**マウント後に `window.location.search` を読む**方式にし、/shop の静的生成を維持（動的レンダリングに落とさない）。
   `track()` の `to` も合成後URLを送るのでクリック時点でも記事名が残る。
3. **`src/pages/chat.tsx`** — `salon_open` に `via` / `inboundContent` を追加。着地側で記事名を受け取れるようにした。
4. **`docs/analytics-events.md`** — メタルプリント／オフィスアート系イベント4種と「アトリビューション規約（3ホップ問題）」の節を追加。パラメータの意味と読み方を表で明文化。
