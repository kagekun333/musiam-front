**最初にやること**: `docs/FABLE_WORKLOG.md`を読み、これまでの経緯（第1〜3セッションで552通の構成多様化が完了済み、sponsoredリンクは66件で外部商品は7件のみ）を把握する。次に`docs/PRODUCT_AND_AFFILIATE_STRATEGY.md`で運用ルールを再確認し、`docs/PRODUCT_CANDIDATES_100.md`で今回の候補100件に目を通す。今回の作業も`FABLE_WORKLOG.md`に「第4セッション（バッチE）」として追記し続けること。

**今回のゴール**: `PRODUCT_CANDIDATES_100.md`の候補から実在確認が取れたものを、テーマの合う手紙に実際に`{sponsored}`リンクとして組み込む。目標は「外部商品を週1〜2回」ペース。現状7件しかないため、今回のセッションで最低でも20〜30件、時間が許す限りそれ以上の追加を目指す。552通全部を埋め切る必要はないが、明らかに手薄な期間（後述）を優先的に埋めること。

**手薄な期間（優先して埋める）**
現状、外部商品リンクがあるのは 2025-01, 2025-01, 2025-04(×2), 2025-07, 2025-12 のみ。**2025年8月〜11月、2026年1月〜6月は外部商品リンクが1件もない。** この6か月分を最優先で埋めること。すでにsponsoredリンクがある2025年1〜3月（自著リンクが密集している期間）には、外部商品を無理に追加しなくてよい。

**進め方（推奨フロー）**

1. **候補の絞り込みとASIN検証**: `PRODUCT_CANDIDATES_100.md`の中から、特に「7. 家電・ガジェット紹介」「8. 暮らし・内省系」「9. 健康・生活リズム」「2. 音楽制作ガジェット」「3. 執筆・読書」「4. AI・PC周辺機器」「5. 文房具・デスク環境」の各ジャンルを優先的に検証する（実在確度が高く、汎用的にどの月にも合わせやすいため）。「10. 時事連動ガジェット」枠は個々の実在・発売時期の確度が低いため、WebSearchで裏取りできたものだけ採用し、できなければ丸ごとスキップしてよい。
   - 各候補についてWebSearchで`site:amazon.co.jp [商品名]`を検索し、実際に`/dp/ASIN`が商品名付きで出たものだけ「実在確認済み」とする。
   - 確認できない商品は本文に組み込まず、候補リストからは一旦外す（`<!-- TODO: ASIN未確認 商品名: XXX -->`のような形でログに残すのはよいが、本文には入れない）。
   - 1回のWebSearchで複数候補をまとめて検索してもよい。効率を優先してよい。

2. **手紙とのマッチング**: 実在確認が取れた商品ごとに、テーマの合う未リンクの手紙を選ぶ。選定時は以下を守ること。
   - 対象は sponsoredリンクが未実施の486通（`grep -L sponsored content/letters/*.md`等で機械的に洗い出せる）。
   - 政治・皇室・戦争・災害・訃報・追悼回には商品を入れない（`FABLE_WORKLOG.md`にある「導線なし」判断の手紙一覧を参照し、同じ基準を踏襲する）。
   - 月次決算回（各月末、A型維持と記録されている手紙）には基本入れない。
   - 1通につき商品は1つまで。
   - 商品ジャンルと手紙の内容が自然に合うことを最優先する。無理にこじつけない。合う手紙が見つからない商品は無理に使わなくてよい。

3. **本文への組み込み**: 該当手紙の本文中、自然な流れの一文に`[表示テキスト](https://www.amazon.co.jp/dp/確認済みASIN?tag=hakusyaku04-22){sponsored}`を織り込む。リンク文言は毎回変える（「〜を使っています」「〜が手元にあります」「〜で聴き比べました」等、パターンの単調な繰り返しを避ける）。frontmatter（title/date/keywords）は変更せず、本文（body）のみ編集する。大きく内容が変わる場合のみdescriptionを更新してよい。署名「**ABI伯爵**」は必ず維持する。

4. **記録**: `docs/FABLE_WORKLOG.md`に「第4セッション（バッチE）」として、検証できた商品と却下した商品（理由付き）、実際にリンクした手紙一覧（手紙名・商品名・ASIN）、月ごとの追加件数、次セッションへの引き継ぎ事項を追記する。

**やってはいけないこと（これまでと同じ・厳守）**
- 実在しないASIN・URLを創作しない。確認できない商品は本文に組み込まない。
- 1通につき商品紹介は基本1つまで。
- `docs/OTHER_PRODUCT_TRACKS.md`側の話題（グッズ/NFT/レコード/コーヒーOEM/家電の自社販売）には手を出さない。
- 政治・皇室・戦争・災害・訃報・追悼回、月次決算回には商品を入れない。
- 署名「**ABI伯爵**」は必ず維持する。
- 使える記法は`##`/`###`見出し・`**強調**`・`[text](url)`・`[text](url){sponsored}`のみ。リスト・引用・画像は使わない。
- 本番への反映（git push）は行わない。

**検証（「完了」と報告する前に必ず行うこと）**
1. 実際に編集したファイルをツールで読み直し、リンクが自然な文脈に入っているか目視確認する。
2. 全552通に対して機械チェックを行い、エラー0件を確認する: (a) 署名が末尾にあること、(b) `[text](https://www.amazon.co.jp/dp/ASIN?tag=hakusyaku04-22){sponsored}`の厳密な記法、(c) 1通1リンク上限を超えていないこと、(d) `## よくある質問`内にsponsoredリンクが混入していないこと、(e) 未対応記法（リスト・引用・画像）が混入していないこと、(f) frontmatterのdateとファイル名の日付が一致していること。
3. 検証方法はPythonスクリプトで全通を走査する形でよい（第1〜3セッションで使った手法を踏襲）。

**利用枠が限られているため**、Effortは高めに設定した上で質を優先し、時間切れが近づいたら新しい商品の検証には着手せず、ログの整理と検証結果のまとめに切り替えること。
