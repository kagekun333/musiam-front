# Fable 5 活用アドバイザリー（今回のプロンプトとは別のレポート）

作成日: 2026-07-02

Fableのプロンプト自体は `docs/FABLE_PROMPT.md` にまとめた。こちらは「Fableというモデルをどう使うと能力を引き出せるか」の調査結果と、「今後Fableに他に何をやらせるとよさそうか」のアドバイスをまとめたレポート。

---

## 1. Fable 5について分かったこと（要点）

- Claude Fable 5は2026年6月9日に一般提供が開始されたが、米国の輸出規制命令（6月12日）により一時全面停止。規制解除を受け、7月1日にClaude Platform／Claude.ai／Claude Code／Cowork向けに再展開された（[Anthropic公式](https://www.anthropic.com/news/redeploying-fable-5)、[MacRumors](https://www.macrumors.com/2026/07/01/anthropic-fable-5-relaunch/)）。
- Pro/Max/Team/一部Enterpriseプランでは、**7月7日まで週間利用上限の50%分をFable 5に使える**。それ以降は利用クレジット経由での継続利用に切り替わる（[Claude公式X投稿](https://x.com/claudeai/status/2072402639644766602)）。「5日間しか使えない」というより、正確には「7/7まではプラン内利用枠が使え、以降は別課金になる」という区切り。
- Fable 5はソフトウェア工学・知識労働・長時間タスクで従来モデルを上回る性能を示すとされ、**タスクが長く複雑になるほど他モデルとの差が開く**、と公式発表されている（[Anthropic公式](https://www.anthropic.com/news/claude-fable-5-mythos-5)）。今回のような「552通の一貫した書き直し＋一貫した商品選定基準の維持」という長時間タスクとは相性がいいはず。

## 2. プロンプトの書き方で分かったこと（公式ガイドより）

Anthropic公式の「Prompting Claude Fable 5」ガイドから、今回のプロンプトに反映した要点（[出典](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5)）:

- **過度な細分化はしない**: タスクを細かいマイクロステップに分解しすぎると、かえってFable 5自身の推論力を阻害する。今回のプロンプトも「フェーズ1→2→3→4」と細かく縛るのではなく、ゴールと制約だけ渡し、進め方自体はFableに計画させる形にした。
- **「聞き返さない」ことを明示する**: 自律実行中は人間がリアルタイムで見ていない前提を明記しないと、「〜してよいですか？」と聞いて止まってしまう。今回のプロンプト冒頭で明記済み。
- **外部メモリ（ファイル）を持たせる**: 会話の文脈だけに頼らせず、計画・判断・進捗をファイルに書き出させながら進めさせる方式が、Fable 5では特に効果が大きいと報告されている（同ガイドいわく、Opus系より効果が大きい）。今回`docs/FABLE_WORKLOG.md`を都度更新させる指示を入れた。
- **証拠に基づく進捗報告**: 「完了しました」と自己申告させる前に、実際のツール結果を見direct確認させる指示を入れることで、過大報告・捏造を防ぐ。今回のプロンプトにも明記（特にAmazonのASIN捏造防止のため重要）。
- **Effort（思考量）の調整**: 難易度に応じてEffortを上げ下げする設計になっている。今回のような長時間・高精度が必要なタスクでは、Effortを高めに設定して実行するのが良さそうです（実行時にEffort設定のオプションがあれば「高」を選ぶことを推奨）。

## 3. 今回のタスクでの実践的な使い方の提案

- **週間利用枠の50%を使い切る前提で、他の軽いタスクは通常モデル（Sonnet等）に振り分ける**のがよい。Fableは「552通の一貫した書き直し」という一番手間のかかる/一貫性が重要なタスクに集中投入し、細かい確認作業・簡単な追加修正は通常モデルに戻して節約する。
- 7/7を過ぎると課金体系が変わるため、**大きな一括実行は今週中に済ませる**。プロンプト側にも「最終日に新規着手しない」の趣旨を含めているが、実際には今日〜数日以内に着手するのが望ましい。
- 実行後は必ず人間側で`docs/FABLE_WORKLOG.md`と実際の差分（`git diff`）を確認してからpushする（プロンプト内の「本番反映はしない」指示と対応）。

## 4. 今後Fableに任せるとよさそうなこと（今回のスコープ外・将来候補）

`docs/OTHER_PRODUCT_TRACKS.md`にある別トラックのうち、Fableの強み（長時間・複雑・一貫性が要るタスク）と相性が良さそうなものを優先順に挙げる。

1. **コーヒーOEM候補への問い合わせ文面一式のドラフト作成**: 5社分、各社の特徴に合わせた問い合わせメール文面を個別に作らせる、といった「量はあるが一貫性のいる」タスクはFable向き。
2. **デジタル限定コンテンツの企画案の深掘り**: 「何を限定にするか」の選択肢を、552通のアーカイブ全体を読み込んだ上で提案させる（人間が全部読むには量が多すぎるが、Fableなら一貫して俯瞰できる）。
3. **手紙全体のSEO/GEOの一貫性監査**: 現状552通のうち、`keywords`frontmatterや構成の一貫性にムラがないかを一括監査させる（今回のリライトと同時に流すのも効率的）。
4. **限定レコード×NFTの実現可能性の本格調査**: 受注生産可能なプレス業者の国内外リストアップなど、リサーチ量が多いタスク。

いずれも「今回のFableプロンプトの後に、同じ手法（外部メモリファイル＋証拠ベース報告＋過度な細分化をしない指示）で使い回せる」という点で、今回作ったプロンプトのひな形はそのまま流用可能。
